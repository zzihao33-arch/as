# CM-HUB 物流面单架构与业务流

本文是上游订单进入 CM-HUB、仓库取单、现场打印和结果回传的边界来源。接口细节以 [上游客户 API](./api/upstream-client-api.md) 与 [OpenAPI](./api/openapi-v1.yaml) 为准；本文明确区分“当前已实现”和“目标架构”，不得把目标能力当作现有接口承诺。

## 不可跨越的边界

- 上游系统主动以服务器到服务器的方式推送订单；上游客户 API Key 只存在于上游服务端，绝不进入 CM-HUB 网页、浏览器存储或前端包。
- 美国云端负责验证、持久化和业务状态。云端不安装打印驱动、不连接仓库打印机，也不执行打印。
- 上游把 PDF 主动推送到云端，云端写入 CM-HUB 管理的美国区面单资产。云端和仓库都不请求上游/境内 `labelUrl`；仓库只通过受控接口缓存其获授权资产。
- 仓库网页直接通过本机 QZ Tray WebSocket 向所选打印机提交内容。不存在、也不计划引入轮询云端的本地 Node 打印桥。
- QZ Tray 接受请求只证明“已提交到本机打印链路”，不证明纸张已经成功输出。没有打印机回执或人工确认时，不得把它表述为物理打印成功。
- 打印结果是 CM-HUB 内部事实。上游不能写入 CM-HUB 打印事件或直接控制 CM-HUB 状态；CM-HUB 通过持久化出站箱可靠投递签名回调。
- Excel 映射和 PDF 文件夹上传是保留的人工兜底流程，不依赖云端推送链路。

## 端到端业务流

```text
上游服务主动推送
  → 美国云端鉴权、幂等处理并持久化为 CM-HUB 记录
  → 上游主动上传 PDF，云端校验 SHA-256 和 PDF 结构并保存为 CM-HUB-owned 面单资产
  → 仓库用户通过 HttpOnly 会话登录，受控交付通道把获授权记录和资产送入仓库网页缓存
  → 扫码匹配、拦截与重复检查
  → 网页直接调用本机 QZ Tray
  → 记录“QZ 已接受/已提交”，与“物理打印成功”分开
  → CM-HUB 持久化结果并写入出站箱
  → 出站投递器向上游发送可重试、可审计的签名回调
```

仓库身份、增量交付、私有 PDF 下载、QZ 提交审计、事务出站箱、签名投递、死信和人工重放均已在仓库代码中实现。生产是否具备这些能力仍取决于 `005`/`006` 迁移、密钥、客户 HTTPS 地址和投递器是否按部署清单启用。物理打印确认仍未实现。当前资产 Adapter 使用美国服务器私有磁盘，未来切换对象存储不改变业务合同。

## 当前实现与目标差距

| 能力 | 当前已实现 | 目标/未来 |
| --- | --- | --- |
| 上游写入 | `POST /api/v1/shipments`；客户与可轮换 Key 分离，Key 具备读写作用域；完整原始载荷和幂等结果持久化 | 保持主动推送；不增加浏览器持有的上游 Key |
| 上游查询 | `GET /api/v1/shipments/by-first-leg/{firstLegTrackingNo}` | 是否保留及返回字段由正式外部合同决定 |
| 状态所有权 | 新记录由 CM-HUB 写为 `RECEIVED`；上游请求不能设置状态 | CM-HUB 根据资产准备、仓库处理和回调结果推进内部状态 |
| 面单 | 上游可通过受鉴权的 PDF 上传接口主动写入；云端以内容哈希在私有目录保存 CM-HUB-owned 资产。`labelUrl` 只作兼容元数据且不会被云端抓取 | 后续可把存储 Adapter 切换到美国区对象存储；不改变业务接口 |
| 仓库取单 | `/warehouse/v1` 使用 HttpOnly 会话、仓库成员关系和客户授权；浏览器按单调修订号增量同步业务字段，并通过受控接口把私有 PDF 写入 IndexedDB | 增加后台账户/授权管理与缓存容量运维工具 |
| 现场打印 | 网页通过 QZ Tray 直连本机打印机；云端面单与人工 Excel/PDF 兜底共用扫码、拦截和重复保护 | 保持无本地 Node 桥；未来接入可靠的物理打印证据 |
| 结果回传 | `/warehouse/v1/print-attempts` 原子写入打印事实与出站事件；投递器使用 HMAC-SHA256、租约、退避、死信和人工重放；不会把 QZ 接受误写成物理成功 | 未来接入可信的物理打印证据时新增事件，不篡改现有语义 |

## 运行与失败语义

1. 上游超时重试必须复用同一个幂等键；完整请求历史与响应持久化到 `inbound_messages`。同一键配不同载荷会被拒绝，重复推送不等于重复打印。
2. 物流数据与 PDF 可分步推送；资产上传完成前记录保持不可打印。云端不会反向抓取 `labelUrl`，仓库也不得绕过云端直接下载该 URL。
3. 仓库断网时，已进入本机缓存的 CM-HUB 资产可以继续按现场策略处理；尚未缓存的任务不得伪装为可打印。
4. QZ 返回接受后若无法取得物理打印证据，只能记录“已提交/结果未知”。重打必须继续执行拦截和重复保护。
5. 回调失败不回滚已经发生的仓库事实；出站箱保留事件并重试，直到成功或进入人工处置。
6. 云端链路不可用时，操作员可切换到手工 Excel/PDF 流程。该兜底产生的本机记录不应冒充已同步的云端回调。

## 安全与所有权

| 资产或凭据 | 所有者 | 允许出现的位置 |
| --- | --- | --- |
| 上游客户 API Key | 上游系统 | 上游服务端密钥存储、CM-HUB 服务端哈希 |
| 上游面单源 URL | 上游/云端摄取流程 | 美国云端服务端；不得作为仓库下载地址 |
| CM-HUB 面单资产 | CM-HUB | 美国区受控存储、授权的仓库缓存 |
| 仓库会话 Cookie | CM-HUB 仓库用户 | 浏览器 HttpOnly/Secure Cookie、服务端 SHA-256 哈希；不进入 JavaScript |
| 工作站安装标识 | CM-HUB 仓库工作台 | 当前浏览器 localStorage；只用于审计关联，不作为认证凭据 |
| QZ 私钥 | CM-HUB 部署环境 | 服务端签名函数；不得进入浏览器 |
| 出站回调签名密钥 | CM-HUB 与对应上游客户 | CM-HUB 服务端 AES-256-GCM 密文 + 服务端主密钥；上游服务端密钥存储；不进入浏览器 |
