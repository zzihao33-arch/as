## 1. 产品概述

CM-HUB 面向海外仓现场换单、单据处理和内部运营，解决上游物流数据到达美国仓库后，仓内多台电脑持续扫码、匹配面单、调用本机打印机并留存处理结果的问题。

系统由两部分组成：

1. **云端物流服务**：接收上游货代主动推送的订单、物流单号和 PDF 面单，在美国服务器完成鉴权、幂等处理、持久化和仓库交付。
2. **仓库工作台**：仓库人员通过浏览器登录，在多台 Windows 电脑上同步云端面单或导入本地 Excel/PDF，扫码后通过 QZ Tray 驱动本机打印机。

系统同时提供拦截名单、BOL 管理、考勤薪酬计算等仓内工具。云端不直接连接打印机，也不在仓库电脑运行 Node 轮询打印桥。

### 1.1 产品愿景

```text
上游主动推送订单和面单
  → 美国云端鉴权、留存和分发
  → 所有仓库工作台同步数据
  → 仓内扫码、拦截、换单和 QZ 本机打印
  → CM-HUB 留存操作事实
  → 向数据所属上游客户回传处理结果
```

### 1.2 核心原则

- 上游主动推送，CM-HUB 不反向请求境内服务器拉单。
- 上游 API Key 只用于服务器间调用，不进入浏览器。
- 所有有效仓库成员共享全部上游物流单据；客户代码只标识数据来源、API Key 和回调归属。
- 每台仓库电脑作为独立工作站登记，打印记录关联仓库、账号和电脑。
- 云端持有业务数据和私有面单资产，打印仍由网页通过 QZ Tray 在本机完成。
- QZ 接受任务只代表“已提交打印”，不代表纸张已经物理输出。
- 云端链路故障时保留 Excel/PDF 本地导入作为现场兜底。

## 2. 用户与权限

### 2.1 用户类型

| 用户 | 主要任务 | 当前权限 |
| --- | --- | --- |
| 仓库操作员 `OPERATOR` | 同步面单、扫码、首次打印和查看作业日志 | 基础仓内作业 |
| 仓库主管 `SUPERVISOR` | 创建/发布/关闭共享批次、拦截维护、BOL、异常处理和单机应急 | 由权限目录授权，不建设未定义的通用审批流 |
| 系统管理员 `SYSTEM_ADMIN` | 全局账户、角色、权限、安全审计和回调管理 | 全局授权，不属于某一个上游客户 |
| 上游客户系统 `Client` | 推送并查询自身物流数据、上传 PDF | 使用独立 API Key 和作用域，不是仓库登录用户 |

### 2.2 登录与会话

- 新版登录字段为全局唯一登录账号和密码；仓库代码、邮箱、工号和上游 API Key 都不是登录凭据。
- 会话通过 `HttpOnly`、`Secure`、`SameSite=Strict` 不透明 Cookie 保存；每次 8 小时，可续期，单次登录绝对上限 16 小时。
- 单账号连续失败 5 次锁定 30 分钟；系统管理员可手动解锁。
- 管理员创建账户时系统生成只展示一次的强随机临时密码，首次登录强制修改。
- 账号、仓库或成员关系被停用后，不得继续恢复有效会话。
- 当前不开放公众注册；首个管理员由服务端命令创建，后续成员由仓库管理员接口创建。
- 后端已经提供成员列表、创建、角色调整和停用接口；前端成员管理页面尚未实现。

### 2.3 仓库、账号与工作站关系

```text
仓库用户 ──成员关系/角色──> 仓库
                               └─ 工作站 A（浏览器安装实例）
                               └─ 工作站 B（浏览器安装实例）

全部有效仓库成员 ──可处理──> 全部上游客户物流数据
```

- 多台电脑不需要创建上游客户代码；每台电脑登记为一个工作站即可。
- 工作站标识只用于操作审计，不是登录凭据。
- 账号状态、仓库成员关系和角色继续生效；“全局可见”不代表未登录用户可以读取数据。

## 4. 核心业务流程

### 4.1 云端物流闭环

```text
上游使用 API Key + 幂等键推送物流单据
  → CM-HUB 提取核心字段并完整保存 raw_data
  → 上游主动上传 PDF 面单
  → 美国服务器校验 PDF/SHA-256 并私有保存
  → 仓库浏览器按单调游标增量同步
  → PDF 校验后写入本机 IndexedDB 缓存
  → 扫码、拦截、重复保护和 QZ 提交
  → 本机 outbox 幂等回传打印事实
  → MySQL 事务出站箱
  → 对应上游客户的签名回调（生产暂未启用）
```

### 4.2 共享导入扫码流程（待发布）

```text
主管 A 导入多个 Excel + 多个 PDF 文件夹/ZIP
  → 云端保存草稿映射和私有 PDF
  → 映射与 PDF 一一对应后发布共享批次
  → A、B、C、D 无需再次导入
  → 任一工作站扫码时先检查全局拦截并原子占用单号
  → 仅占用成功的工作站获取 PDF
  → QZ Tray 提交到本机打印机
  → 本机 outbox 持久化结果并幂等回传
```

### 4.3 断网单机应急

- 共享服务不可用时默认停止打印，防止静默跳过最新拦截。
- 仓库主管或系统管理员可为当前工作站启用单机应急；业务已确认不同电脑处理不同实体包裹。
- 应急模式只能使用当前电脑已验证的映射/PDF 与最后一次同步的拦截版本。
- 界面持续显示拦截同步时间、本机缓存状态、待回传数量与恢复连接操作。

## 5. 功能需求

### 5.1 仓库工作台身份

- 未登录访问任何业务路由时显示统一仓库登录页。
- 登录成功后恢复当前仓库、用户、角色及工作站信息。
- 同一账号可在多台电脑登录；每台浏览器生成独立安装标识并登记工作站。
- 工作站被停用后不得写入新的云端打印尝试。
- 管理员可以通过后端接口创建成员、调整角色和停用成员；系统拒绝停用或降级最后一个有效管理员。

### 5.2 扫码打单

#### 5.2.1 云端面单同步

- 登录后自动读取本机云端缓存，并立即发起增量同步。
- 默认每 60 秒及浏览器恢复联网时再次同步。
- 服务端按单调修订游标分页交付，每页最多 200 条；浏览器逐页落库后保存游标。
- 只把状态为 `READY_TO_PRINT` 且存在当前面单资产的记录加入可打印库。
- PDF 下载后必须核验 `%PDF-` 文件头、字节数和 SHA-256，校验通过后才能写入 IndexedDB。
- 扫描头程单号或末端快递单号均可命中云端记录。
- 云端缓存按仓库标识隔离本机存储，避免不同登录仓库复用错误游标。

#### 5.2.2 Excel 映射导入

- 支持点击或拖拽一次选择多个 `.xlsx` / `.xls` 文件，并可分批继续追加。
- 支持两种表头映射：旧模板 `头程单号 → 快递单号`；新模板 `运单号 → 参考单号`。
- 新模板中运单号等同头程单号，参考单号等同快递单号。
- 对每个工作簿遍历工作表，读取可识别表头后的有效行。
- 多文件映射合并；相同头程单号以后解析的数据为准。
- 无法解析的部分文件被跳过并提示，不覆盖已经成功导入的数据。
- 优先在 Web Worker 中解析，Worker 不可用时退回主线程。

#### 5.2.3 PDF 面单库导入

- 支持选择或拖拽 PDF 文件夹、多个 PDF 文件和多个 ZIP 压缩包。
- 支持连续添加多个来源，累计最多保留 20,000 个 PDF。
- ZIP 在浏览器本地解压，只提取 `.pdf` 文件。
- 文件名去除扩展名后作为面单索引；同批或已有库中出现相同/规范化同名文件时，整次导入阻断，避免静默覆盖错误面单。
- 文件夹来源保存目录访问授权，刷新后重新读取；直接文件和 ZIP 内容按批次写入 IndexedDB。
- 本地会话超过约 24 小时后按过期策略清理；无法恢复目录权限或缓存不完整时必须提示重新授权/导入。
- 导入后展示 Excel 条目、PDF 数量、来源数量和匹配预检结果。
- 当映射数 × PDF 数超过 1,000,000 次比较时，完整预检延后，扫码仍使用索引匹配。

#### 5.2.4 匹配规则

1. 扫描值去除首尾空格和控制字符，并忽略大小写。
2. 云端缓存中的头程单号或快递单号精确匹配优先。
3. 本地模式先使用头程单号查找 Excel 映射，再同时使用扫描值和快递单号查找 PDF。
4. PDF 顺序为：规范化精确匹配 → 文件名开头匹配 → 文件名包含匹配。
5. 任一步出现多个候选时必须阻断，提示清理重复或使用唯一文件名。
6. 没有找到云端面单或本地 PDF 时不得提交打印。

#### 5.2.5 扫描保护与反馈

- 扫码枪按键盘输入处理；人工输入后按 Enter 也可提交。
- 会话文件、云端缓存或拦截名单仍在恢复时，不得静默开始打印。
- 拦截名单损坏或不可用时，扫码工作台采用 fail-closed 策略阻断打印。
- 同一扫描值已有任务在提交时，阻止并发重复任务。
- 五分钟内已经提交或结果未知的同一单号再次扫描时弹出二次确认。
- 强制重复打印必须明确确认，并在日志中记录 `DUPLICATE_OVERRIDE`。
- 处理结果通过文字、颜色、状态区域和音效共同反馈。

#### 5.2.6 QZ Tray 打印

- 只使用浏览器到本机 QZ Tray 的 WebSocket 调用真实打印机，不运行 Node 打印代理。
- 过滤 PDF24、Microsoft Print to PDF、OneNote、Fax、XPS、WPS PDF、Adobe PDF 等虚拟设备。
- 只有一台真实打印机或存在默认设备时可自动选择；多台设备且没有选择时要求人工选择。
- 打印 PDF 使用 Base64 内容和当前打印设置提交，30 秒未返回时记录 `RESULT_UNKNOWN/TIMEOUT`，不能直接认定失败或成功。
- QZ Promise 成功只显示“已提交/已接受”。
- QZ 证书和 RSA-SHA512 签名通过 `/api/qz-certificate`、`/api/qz-sign` 获取；私钥不得进入前端包。

#### 5.2.7 日志与云端审计

- 本机日志分为打印记录、导入记录、系统状态，最多保留 5,000 条，按 20 条/页显示。
- 日志保存到 IndexedDB；落盘失败不阻塞主打印流程。
- 云端任务的 `SUBMITTED`、`FAILED`、`RESULT_UNKNOWN`、`BLOCKED` 先写入本机 outbox，再使用同一个 `clientAttemptId` 重试回传。
- 服务端验证工作站、当前面单资产和幂等载荷，打印尝试与出站回调事件在同一事务写入。

### 5.3 拦截名单

- 支持单条输入、批量粘贴和 10 秒扫码录入模式。
- 单号格式为 8–25 位字母、数字或连字符，忽略大小写并拒绝重复。
- 展示单号、添加时间、来源和删除操作。
- 名单保存在当前浏览器 IndexedDB，并在同一浏览器页面间同步。
- 命中时显示全屏阻断弹窗、播放警报并写入日志；关闭弹窗后不会自动打印。
- 当前不跨电脑同步；换机或清理浏览器数据会丢失名单。

### 5.4 BOL 管理

- 流程为记录列表 → 编辑与实时预览 → 人工核对 → 输出。
- 支持 GOFO、YWE、UniUni、SpeedX、SwiftX、USPS、UPS、Fedex、DHL 多渠道。
- 每个渠道分别记录包裹数、箱数、板数；数量必须是非负整数。
- BOL 单号、至少一个渠道和有效提货时间为必填项。
- 同一浏览器内拒绝重复 BOL 单号，修改后版本号递增。
- 生成 Letter 纵向版式，可使用浏览器打印或下载 PDF。
- IndexedDB 最多保留最近 500 条 BOL 记录，并记录版本和打印次数。
- 当前不跨电脑同步，也不是正式云端归档。

### 5.5 考勤与薪酬

- 考勤以云端打卡记录为唯一数据源，旧的考勤 Excel 导入入口和浏览器解析流程已移除。
- 固定仓库电脑通过已登记工作站和现场动作抓拍打卡，浏览器位置仅作为辅助信号；移动端必须取得精度不超过 50 米的位置并命中启用的仓库围栏。
- 随机提示眨眼或张嘴并抓拍现场照片，但不做人脸身份识别、不建立人脸模板；所有接受和拒绝的尝试均保留审计事实。
- 每个工作日一组上班/下班打卡；跨午夜归属上班日期，连续时长超过 18 小时进入待复核。完整打卡对固定扣除 1 小时午休。
- 员工可在异常发生后 72 小时内提交精确修正时间；仓库主管审批，且不得审批自己的申诉。通过后保留修正前后快照并重新计算。
- 班次按生效日期配置工作日、上下班时间、迟到和早退宽限；打卡地支持 50–1000 米圆形围栏。
- 按周一至周日统计：每周前 40 小时为常规工时，超过部分按 1.5 倍基础时薪计算 OT。
- 当前油补为 `$19.50 × 油补天数`。
- 支持按生效日期维护基础时薪，并按核算周期调整奖金和油补天数。
- 缺少有效基础时薪时标记“计算阻断”，禁止导出。
- 导出前先在服务端固化不可变薪酬快照，再生成工作表 `考勤及工时汇总`；末列名称为“核对”，无异常显示“已核对”。
- 位置、动作与照片证据保留 6 个月；工时、薪酬计算和最小员工快照保留 6 年。删除账号后不保留联系方式或照片。
- 当前不承担薪资发放、税务计算或法定考勤归档。

### 5.6 工作概览与设置

- 工作概览提供扫码打单、BOL 和打印机设置快捷入口。
- 支持跟随系统、浅色、深色主题及移动端抽屉导航。
- 打印机和音效设置在扫码工作台内以设置面板呈现。
- 音效支持开关、0–100 音量、成功音试听、长按失败音试听和现场增强模式。
- 系统状态页和本日运营概览目前是占位能力，不能作为生产监控使用。

### 5.7 上游客户 API

- 基址为 `https://api.cmhubtool.com/api/v1`。
- 所有上游请求必须携带 `X-API-Key`；Key 归属于客户，可独立轮换、撤销并限制作用域。
- 当前作用域为 `shipments:write`、`shipments:read`、`labels:write`。
- 创建/更新物流单据必须使用幂等键；相同键配不同载荷返回冲突。
- 接口提取订单号、头程单号、快递单号、收件信息、商品等核心字段，并将整个原始请求保存为 `raw_data`。
- 未定义字段采用兼容模式保存，不因上游多传字段而拒绝。
- 上游不能设置 CM-HUB 内部状态，也不能写入打印事件。
- 上游主动上传 `application/pdf` 面单；服务端校验文件结构、大小和可选 SHA-256。
- 客户只能通过上游查询接口读取自身物流单据；仓库端可见性规则与上游 API Key 隔离。

### 5.8 上游结果回调

- 回调事件来源于 CM-HUB 已记录的仓库打印尝试，不接受上游反向写入。
- 每个客户配置独立 HTTPS 回调地址和 HMAC-SHA256 签名密钥。
- 签名密钥以 AES-256-GCM 密文保存，主密钥只存在于服务端配置。
- 出站箱支持租约、指数退避、死信、逐次尝试审计和管理员人工重放。
- 当前生产投递器保持关闭，完成真实客户 URL、密钥、验签和去重联调前不得宣称闭环已上线。

## 8. 非功能需求

### 8.1 性能

- 扫码热路径必须使用内存索引，不得在每次扫描时线性遍历数千条映射和面单。
- Excel 映射解析优先放入 Worker；考勤不再从 Excel 解析。
- 大批 PDF 分批写入 IndexedDB；导入 1,000 个以上候选文件时应显示明确读取状态。
- 云端 PDF 下载限制并发数，避免首次同步大量面单时阻塞页面。
- 日志和 BOL 列表采用上限、分页或按需渲染，页面切换不得出现明显残影和长时间冻结。

### 8.2 稳定性

- 应用级错误边界必须阻止单个页面异常导致浏览器退出或回到首页。
- 路由切换不得残留前一页面视觉内容；扫码页面不使用悬停位移、抖动等影响操作稳定性的动效。
- Redis、MySQL 或私有面单存储不可用时，健康检查返回失败；关键鉴权和幂等逻辑采用 fail-closed。
- 本机缓存失败时必须清楚区分“当前内存可用”和“刷新后不可恢复”。

### 8.3 安全与隐私

- 上游 API Key、MySQL 密码、QZ 私钥、回调签名密钥不得写入前端包、浏览器存储、日志或仓库。
- API Key 只保存密码学哈希；仓库密码使用带随机盐的安全哈希。
- PDF 不配置 Nginx 公开目录，只能经仓库会话接口读取。
- 仓库接口只允许精确配置的前端 Origin，并使用带凭据 Cookie。
- `raw_data` 用于对账和兼容，不直接下发到现场浏览器。
- 日志和回调响应只保存必要摘要，不保存签名密钥或完整敏感响应正文。

### 8.4 现场兼容性

- 主要目标环境为 Windows、Chrome、QZ Tray 和真实标签打印机。
- 高频作业必须支持扫码枪和键盘，无障碍状态不能只靠颜色表达。
- 云端暂时不可用时，允许使用已经缓存的云端面单或切换到手工 Excel/PDF 兜底。

## 9. 验收标准

| 模块 | 验收条件 |
| --- | --- |
| 登录 | 正确仓库代码、邮箱和密码可进入工作台；错误凭据统一失败；刷新可恢复有效会话 |
| 多工作站 | 同一仓库多台电脑可分别登记工作站并产生可区分的打印审计 |
| 全局可见性 | 新上游客户数据无需维护仓库绑定，即可被任一有效仓库成员同步；停用成员仍不可访问 |
| 上游写入 | 合法 API Key 和幂等键可写入；未知字段保存在 `raw_data`；跨客户查询不可见 |
| PDF | 只有通过结构、大小和哈希校验的 PDF 才能成为当前面单资产 |
| 本地导入 | 多 Excel 能合并两种模板；多文件夹/ZIP 累计不超过 20,000；重复文件名阻断导入 |
| 匹配 | 唯一匹配才能打印；多候选和缺失 PDF 必须阻断并记录原因 |
| 拦截 | 名单命中或名单存储异常时不发起打印，并显示阻断反馈 |
| 重复保护 | 五分钟内重复单号默认阻断；只有明确确认才能覆盖并留痕 |
| QZ | 虚拟打印机被过滤；QZ 离线、授权失败、多设备未选和 30 秒超时都有可诊断反馈 |
| 打印语义 | QZ 接受只显示“已提交”；没有可靠证据时不出现“物理打印成功” |
| BOL | 多渠道数量独立保存；确认后可打印/下载；本机最多保留 500 条 |
| 考勤薪酬 | 周工时、OT、午休和油补计算符合当前规则；缺时薪阻断导出；末列为“核对” |
| 回调 | 启用前完成签名、重试、去重、死信和重放联调；当前禁用状态不得发送生产回调 |

## 10. 当前缺口与优先级

| 优先级 | 缺口 | 影响 | 下一步 |
| --- | --- | --- | --- |
| P0 | 全局仓库可见性代码尚未发布 | 新增客户后当前生产仍需要手工绑定 | 经批准后全量发布并验证新客户自动可见 |
| P0 | 私有面单磁盘缺少已验证的异机备份与容量告警 | 磁盘故障或空间耗尽影响面单交付 | 接入加密备份、容量监控，后续评估美国区对象存储 |
| P0 | 正式上游客户与回调尚未联调 | 尚不能宣称完整业务闭环 | 创建正式客户 Key，完成订单/PDF/验签/去重/回调验收后再启用投递器 |
| P0 | 共享扫码批次与全局拦截尚未发布 | 生产环境仍不能跨电脑共享人工导入与拦截数据 | 经批准后执行 `008`、发布并完成双电脑并发验收 |
| P1 | 账户与角色管理尚未发布 | 生产环境仍依赖旧身份入口 | 经批准后执行 `007`、校验管理员登录名并完成权限矩阵验收 |
| P1 | 系统状态和本日运营概览为空态 | 管理人员无法查看真实健康和产能 | 接入扫描量、失败率、同步状态、QZ 健康和磁盘容量 |
| P1 | 拦截页异常提示与扫码 fail-closed 文案不一致 | 可能误导现场对风险状态的理解 | 统一为“存储异常即阻断打印” |
| P1 | PDF 导入提示存在“以后导入为准”，但实际冲突会阻断 | 操作员可能误解覆盖规则 | 统一文案为“重名必须先处理” |
| P1 | BOL 使用浏览器打印且无云端审计 | 弹窗策略和本机数据限制可影响作业 | 评估 QZ 输出和云端 BOL 归档 |
| P2 | 午休、OT、油补规则写死 | 不适应不同站点或政策 | 参数化规则并记录生效版本 |

## 11. 明确非目标

- 不提供公众自助注册；仓库账号由内部管理员创建。
- 不允许上游 API Key 登录仓库工作台。
- 不允许上游直接控制打印机、写入打印事件或修改 CM-HUB 内部状态。
- 不在仓库电脑运行 Node 轮询打印桥，云端也不连接本机打印机。
- 当前不把 BOL、考勤薪酬作为正式云端归档；扫码导入批次和拦截名单已进入共享云端模型。
- 当前薪酬模块不负责税务、工资发放或劳动合规判断。
- 没有打印机可靠回执时，不提供物理出纸确认。
