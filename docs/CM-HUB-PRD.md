## 1. 产品概述

CM-HUB 包含上游服务器端物流对接与仓库现场运营工作台。工作台将扫码、面单匹配与打印、拦截单管理、BOL（Bill of Lading）生成，以及考勤薪酬计算集中在同一网页内；云端 API 当前独立接收并持久化上游物流单据。

产品服务于持续、高频、对准确性敏感的现场流程。操作员应能在不中断作业节奏的情况下完成扫码和打印；主管能完成异常拦截、单据输出及考勤核对；设备管理员能确认本机打印环境可用。

### 1.1 产品愿景

以“当前电脑即工作站、云端不打印”为原则，逐步形成“上游主动推送 → 美国云端持有 CM-HUB 面单资产 → 仓库缓存 → QZ 提交 → 出站签名回调”的闭环，同时保留 Excel/PDF 手工兜底。

### 1.2 当前版本定位

- 面向 Windows + Chrome 的本机作业工作台。
- 前端采用 React、TypeScript、Vite 与 Arco Design；文件解析、BOL/PDF 生成主要在浏览器本地完成。
- 面单直打统一通过 QZ Tray WebSocket 驱动本机真实打印机。
- 云端服务已实现 `/api/v1` 下的上游物流单据写入/查询、PDF 主动上传、MySQL 持久化、Redis 限流/幂等和美国服务器私有面单存储。
- `/warehouse/v1` 已实现仓库登录/角色、增量交付、私有 PDF 下载和 QZ 提交审计；云端已实现事务出站箱、签名投递、退避、死信和人工重放。规范边界以 [架构与业务流](./architecture.md) 为准。

## 2. 问题与目标

### 2.1 要解决的问题

1. 操作员需要在 Excel 映射和大量 PDF 面单中快速找到与扫码单号对应的面单，并直接打印。
2. 同一单号的重复扫描或需要拦截的快件可能导致重复出单、错误出库或现场返工。
3. BOL 填写、核对、打印与归档分散，易产生渠道、数量或提货时间错误。
4. 月度考勤表中的上下班时间、加班、奖金和油补需要人工计算，核对成本高。
5. 浏览器不能直接稳定管理系统打印机，现场人员需要清晰判断 QZ Tray、打印机和签名状态。

### 2.2 目标

- 让操作员完成“导入 → 扫码 → 匹配 → 直打 → 留痕”的短路径操作。
- 在打印前拦截命中名单及五分钟内的重复扫描，并允许有意识地覆盖重复保护。
- 将 BOL 生成标准化为可校验、可预览、可打印/下载的流程。
- 将月度考勤自动转化为按周工时、加班和薪酬汇总，并保留人工修正入口。
- 将本机打印依赖、异常和恢复路径显式呈现。
- 建立不暴露上游 Key 和源面单 URL 的受控云端到仓库链路，并由 CM-HUB 可靠回调业务结果。

### 2.3 非目标（当前版本）

- 不提供公开注册、复杂审批流或跨仓共享；仓库账号只能由管理员受控创建。
- BOL、考勤草稿和本机拦截名单当前不做跨设备同步。
- 不允许上游控制 CM-HUB 状态或写入打印事件；不把 QZ 接受请求等同于物理打印成功。
- 不保证 BOL、打印日志、拦截名单在不同浏览器或不同电脑之间同步。
- 不承担税务、正式薪资发放或考勤原始数据的长期合规存档。

## 5. 功能需求

### 5.1 扫码打单工作台

#### 5.1.1 数据导入与会话恢复

**用户故事**：作为操作员，我希望先导入单号映射表与面单 PDF 文件夹，之后可以连续扫码并打印对应面单。

**功能要求**：

- 支持上传 `.xlsx` / `.xls` 映射表；读取首个工作表中的“头程单号”和“快递单号”字段，生成单号映射。
- 支持选择 PDF 文件夹；不支持目录选择器的浏览器可退化为批量选择文件。仅接受 PDF，按去掉扩展名后的文件名建立面单索引。
- 显示已导入映射条数、PDF 数量、文件名和成功/失败原因。
- 将映射、文件摘要及 PDF 文件（或经授权的目录句柄）保存至浏览器本机会话缓存；刷新后自动尝试恢复。
- 若恢复尚未完成、浏览器禁用缓存，或重新访问目录需要权限，必须提示用户，且不能静默打印错误数据。
- Excel 解析放在 Web Worker 中，避免大文件影响扫码界面；Worker 不可用时可退回主线程解析。

**匹配规则（当前实现）**：

1. 扫描值先按忽略首尾空格、大小写的方式匹配 Excel 的头程单号。
2. PDF 文件名优先做“以扫描值开头”的匹配，再做“文件名包含扫描值”的模糊匹配。
3. 若已找到 PDF 但没有 Excel 映射，会尝试从 PDF 文件名中反查快递单号。
4. 找不到 PDF 时不允许进入打印，记录失败原因。

> 待统一项：页面提示中存在“PDF 文件名包含转单号”的表述，但实际代码优先以扫描值匹配 PDF 文件名。上线前须确定唯一命名规范，并同步修改解析规则、提示和导入模板。

#### 5.1.2 扫码、风控与打印

**用户故事**：作为操作员，我扫描条码并按回车后，希望系统立即识别、打印并明确告诉我结果。

**功能要求**：

- 扫码枪按键盘输入处理；输入框支持人工输入，回车提交。
- 扫描前检查本机会话文件是否恢复完成。
- 先执行拦截名单校验；命中时显示全屏阻断提示、播放失败警报并记录系统日志，不得提交打印。
- 对过去五分钟内已被 QZ 接受提交的同一规范化单号进行重复检测；命中后弹出确认，而非直接提交。
- 操作员可取消重复扫描，也可显式确认“仍要打印”；强制打印应在日志中标记为 `DUPLICATE_OVERRIDE`。
- 匹配成功时读取 PDF，通过 QZ Tray 提交到本机打印机；失败、超时、未匹配等均应给出文字、视觉和声音反馈。
- QZ Promise 成功只记为“已提交/已接受”，不能宣称纸张已经输出；只有可靠打印机回执或人工核验才能形成物理打印确认。
- 状态反馈至少包括：空闲、处理中、已提交、错误；处理状态最长显示约 4 秒，已提交/错误约 1.2 秒。

#### 5.1.3 QZ Tray 本机打印

**用户故事**：作为设备管理员，我需要知道 QZ Tray 能否发现真实标签打印机，并能安全完成直打。

**功能要求**：

- 仅使用 QZ Tray WebSocket 发现和调用本机打印机；不启动第二套 Node 打印进程。
- 支持“自动选择可直打打印机”或手动选择已发现的真实打印机；记住本机选择。
- QZ Tray 打印机清单应过滤 PDF24、Microsoft Print to PDF、OneNote、Fax、XPS、WPS PDF、Adobe PDF 等虚拟设备。
- 当只存在一台真实打印机或存在默认真实打印机时可自动选用；有多台真实打印机且未选择时，要求操作员先选择。
- 打印请求由 QZ Tray 接收 PDF Base64、目标打印机和渲染选项后提交；不经过 Node 打印代理。
- 需展示 QZ Tray 连接状态、已选打印机、被隐藏的虚拟设备数量以及具体错误原因。

#### 5.1.4 QZ Tray 安全签名

- 前端通过 `/api/qz-certificate` 获取官方数字证书，并通过 `/api/qz-sign` 请求服务端 RSA-SHA512 签名。
- QZ 私钥仅保存在部署环境变量；不得进入前端代码、仓库或浏览器存储。
- 签名接口执行自身的来源授权检查；`QZ_ALLOWED_ORIGINS` 只属于 QZ 签名端点策略，与上游客户认证无关。
- 未配置官方证书/私钥时，系统仍可提示并尝试使用 QZ，但应明确告知可能出现每次打印授权弹窗。
- 新电脑配置需要安装并运行 QZ Tray；设置页提供配置指南入口。

#### 5.1.5 音效与操作日志

- 支持启用/关闭扫码音效、设置 0–100 音量、试听成功音；长按试听失败音。
- 显示音效状态、播放截断次数、最近一次结果及持续时间。
- 日志分为“打印记录、导入记录、系统状态”，按最新优先、20 条/页显示；各分类可单独清空。
- 日志记录时间、扫描/头程单号、快递单号、结果和消息，并至少区分已提交、失败、超时、重复覆盖。
- 日志本机持久化失败不得阻塞扫码打印主流程。

#### 5.1.6 云端集成

- 上游只从服务端主动推送；客户 API Key 永不进入仓库网页。
- 美国云端先持久化物流单据；上游再主动上传 PDF，由云端校验并保存 CM-HUB-owned 面单资产。云端和仓库均不抓取上游/境内 `labelUrl`。（已实现）
- 受控仓库交付合同通过 HttpOnly 会话、成员角色和客户授权，把物流记录及 CM-HUB 面单资产增量送入按仓库隔离的浏览器缓存；不部署 Node 轮询桥。（已实现）
- QZ 提交结果先写入本机 outbox，再由 CM-HUB 第一方接口幂等持久化；`SUBMITTED` 与物理成功严格分离。（已实现）
- 打印事实与回调事件同事务写入；回调使用每客户独立 HMAC-SHA256 密钥、稳定 `eventId`、租约投递、指数退避、死信与管理员重放。（已实现）
- 当前私有磁盘存储可通过既有 Adapter 在后续替换为美国区对象存储。

### 5.2 拦截名单

**用户故事**：作为主管，我希望将风险单号加入本机硬拦截名单；操作员扫描到该单时必须停止打印。

**功能要求**：

- 支持手工输入、粘贴或开启 10 秒扫码模式录入单号。
- 单号仅接受 8–25 位字母、数字或连字符；应提示格式错误和重复录入。
- 列表展示单号、添加时间、来源（扫码录入/手动录入）及删除操作。
- 名单保存至浏览器 `localStorage`，当前工作台与名单页应实时共享。
- 扫码命中后显示不可忽略的阻断提示，用户仅可确认“已处理”以关闭提示；关闭后不自动打印。
- 当本地名单读取损坏或无法写入时，给出明显警告，并在扫码日志中记录“拦截可能失效”。

### 5.3 BOL 管理

**用户故事**：作为现场主管，我希望快速录入渠道、装载数量及提货时间，确认后生成符合模板的 BOL，并打印或保存 PDF。

**功能要求**：

- 可新建、查看、修改既有 BOL；流程为“记录列表 → 编辑与实时预览 → 核对确认 → 输出”。
- BOL 单号支持扫码或手工输入；同一浏览器内不得重复保存相同规范化单号。
- 支持多选渠道：GOFO、YWE、UniUni、SpeedX、SwiftX、USPS、UPS、Fedex、DHL。
- 每个渠道独立录入包裹数、箱数、板数；切换渠道不得丢失已填写数量。数量可留空，填写时必须为非负整数。
- 必填信息包括 BOL 单号、至少一个渠道及有效提货时间；校验失败需在字段附近提示。
- 编辑时实时预览，输入停止约 500ms 后更新预览；确认前明确要求人工核对模板字段。
- 确认后保存 BOL 版本、创建/更新时间、打印次数和渲染内容；再次编辑版本号递增。
- 以 Letter 纵向版式输出：可在浏览器打印窗口打印，也可生成并下载 PDF。
- 列表展示 BOL 单号、渠道、数量摘要、提货时间、版本和打印次数。

### 5.4 考勤与薪酬

**用户故事**：作为薪酬人员，我上传月度考勤表后，希望系统自动识别员工、工时和异常，能修改必要项并导出可复核的汇总。

**功能要求**：

- 支持上传 `.xlsx` / `.xls`；在后台 Worker 中解析，避免大表阻塞界面。
- 优先识别月度模板：年份月份、至少 7 个日期列、每位员工连续两行（上班/下班）。当识别不到该模板时，降级识别通用日期表头。
- 解析员工姓名、基础时薪、上下班时间、奖金、油补天数；月度模板中可从指定颜色的单元格识别油补标记。
- 每个完整打卡对的净工时为下班减上班后固定扣除 1 小时午休；跨午夜打卡应正确计算。
- 按周一至周日聚合；每周前 40 小时为常规工时，超出部分为加班工时。
- 薪酬公式：`常规工资 = 常规工时 × 基础时薪`；`加班工资 = 加班工时 × 基础时薪 × 1.5`；`油补 = 油补天数 × $19.50`；`应发总额 = 常规工资 + 加班工资 + 奖金 + 油补`。
- 表格内允许人工修正基础时薪、奖金和油补天数；基础时薪缺失或无效时标记为“计算阻断”。
- 识别缺上班/下班打卡、扣除午休后工时为 0、缺少基础时薪等异常；支持按姓名搜索及仅查看异常。
- 导出 Excel：包含“薪酬汇总”和“周工时明细”两个工作表。存在未补齐基础时薪的员工时禁止导出。

### 5.5 工作概览与系统设置

- 工作概览提供进入扫码打单、BOL 管理及打印机设置的快捷入口。
- 顶部支持跟随系统、浅色、深色主题；移动端支持抽屉式导航。
- 打印机设置与音效设置直接承载于扫码打单工作台中，路由跳转到对应设置面板。
- “本日运营概览”和“系统状态”目前尚未接入真实指标或健康检查，不应在对外说明中描述为已完成的监控功能。

## 6. 核心流程

### 6.1 当前手工兜底扫码直打流程

```text
导入 Excel 映射 + PDF 面单库
          ↓
恢复本机会话完成？──否→ 提示等待/重新上传
          │是
          ↓
扫描单号（回车）
          ↓
命中拦截名单？──是→ 全屏阻断 + 失败反馈 + 系统日志
          │否
          ↓
5 分钟内重复提交？──是→ 用户取消 / 明确覆盖
          │否或覆盖
          ↓
匹配 Excel 与 PDF？──否→ 失败反馈 + 打印日志
          │是
          ↓
QZ Tray WebSocket 提交任务
          ↓
接受：已提交反馈 + 计数 + 本机日志（不等于物理出纸）
失败：错误反馈 + 原因日志
```

### 6.2 云端到仓库与上游回调流程（仓库代码已实现，生产待迁移与联调）

```text
上游服务主动推送 → 美国云端鉴权/幂等/持久化
    → 上游主动上传 PDF → 云端校验并保存 CM-HUB-owned 面单资产
    → 受控交付到仓库浏览器缓存 → 扫码/拦截/重复保护
    → 浏览器直连 QZ Tray → 记录“已提交”与物理确认的差异
    → CM-HUB 结果持久化 → 出站箱 → 上游签名回调
```

### 6.3 BOL 输出流程

```text
新建 BOL → 录入单号、渠道、数量、提货时间 → 字段校验
    → 实时预览 → 人工核对确认 → 保存版本
    → 浏览器打印 或 下载 Letter PDF
```

### 6.4 薪酬计算流程

```text
上传考勤 Excel → 后台解析模板/日期 → 计算周工时与 OT
    → 标记考勤/时薪异常 → 人工修正薪资项
    → 全部员工有有效基础时薪 → 导出汇总及周工时 Excel
```

## 7. 数据、存储与接口

| 数据对象 | 当前存储方式 | 保留/限制 | 注意事项 |
| --- | --- | --- | --- |
| Excel 映射、PDF 面单会话 | IndexedDB + `sessionStorage` 标识 | 过期会话约 24 小时后清理 | 本机、同一浏览器；目录权限可能需重新授权。 |
| 拦截名单 | `localStorage` | 未设业务上限 | 本机、同一浏览器；损坏时可失效。 |
| 打印/导入/系统日志 | `localStorage` | 当前仅保留最新 100 条 | 与产品目标的 5,000–10,000 条留痕不一致。 |
| BOL 记录 | `localStorage` | 当前仅保留最新 5 条 | 不适合作为正式归档。 |
| 考勤解析与薪酬计算 | 浏览器内存 | 关闭/刷新后不保留 | 上传文件和导出结果不上传业务后端。 |
| 上游物流单据 | MySQL（云端 API） | 可写入/查询并按单调游标交付仓库 | 仓库只能读取明确授权客户。 |
| 上游面单源引用 | MySQL `label_url` | 兼容保存 URL/可选 SHA-256 | 不是下载合同；云端和仓库均不会抓取。 |
| CM-HUB 面单资产 | 美国服务器私有磁盘 + MySQL 元数据 | PDF 头尾与 SHA-256 校验；内容哈希去重 | 仅通过仓库鉴权接口流式下载；目录不得由 Nginx 公开。 |
| 结果出站箱 | MySQL + 服务端投递器 | 租约、退避、死信、人工重放和完整尝试审计 | 签名密钥以 AES-256-GCM 密文保存。 |

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/qz-certificate` | GET | 读取 QZ 官方证书。 |
| `/api/qz-sign` | POST | 对 QZ 请求进行服务端签名。 |
| `/api/v1/shipments` | POST | 当前：上游服务端创建/更新物流单据；上游不能设置状态。 |
| `/api/v1/shipments/by-first-leg/{firstLegTrackingNo}/label` | PUT | 当前：上游主动上传并保存 PDF 面单资产。 |
| `/api/v1/shipments/by-first-leg/{firstLegTrackingNo}` | GET | 当前：上游查询自身物流单据。 |
| `/warehouse/v1/shipments` | GET | 第一方仓库按单调游标同步获授权物流单据。 |
| `/warehouse/v1/print-attempts` | POST | 幂等记录 QZ 提交结果并原子创建回调事件。 |
| `/warehouse/v1/outbound-events` | GET | 仓库管理员查看获授权客户的回调审计。 |

## 8. 非功能需求

### 8.1 性能与稳定性

- Excel 映射和考勤解析优先放入 Worker；长列表采用分页或虚拟化，避免阻塞操作台。
- 连续扫码反馈应即时，且不能因日志落盘或缓存失败中断主流程。
- 打印超时、QZ 未连接、无真实打印机、未选择多台打印机中的目标设备等场景必须可诊断。

### 8.2 安全与隐私

- QZ 私钥仅可存放在部署平台环境变量中；日志、前端包和浏览器缓存中均不得出现私钥。
- QZ Tray 私有通信仅经本机 WebSocket 进行；网页不得保存或暴露云端客户 API Key。
- 上游面单源 URL 只作兼容元数据；云端和仓库均不抓取。仓库缓存只能保存当前会话获授权的 CM-HUB 面单资产。
- 回调签名密钥仅存在于 CM-HUB 出站投递服务端和对应上游服务端；数据库只保存密文，上游不能通过入站事件改变 CM-HUB 状态。
- 当前产品将业务文件、拦截名单和 BOL 置于浏览器本机，应在界面中说明设备共用、清理浏览器数据和换机带来的数据风险。

### 8.3 可用性与无障碍

- 高频操作支持键盘与扫码枪；焦点态清晰，状态不能仅依赖颜色表达。
- 操作状态使用文字、视觉与音效三重反馈；弱光现场仍应具备足够对比度。
- 大表格具备搜索、异常筛选、横向滚动和分页能力。

## 9. 验收标准

| 模块 | 验收条件 |
| --- | --- |
| 导入与匹配 | 给定符合模板的 Excel 与 PDF 面单库后，系统能显示导入数量；扫码成功找到对应 PDF 时才能提交打印。 |
| 拦截 | 名单中的合法单号被扫描后，不发起打印请求，出现阻断提示并写入系统日志。 |
| 重复保护 | 五分钟内 QZ 已接受过的单号再次扫描时默认不提交；只有确认覆盖后才提交，且日志标记覆盖结果。 |
| 打印机 | 虚拟打印机不显示为直打候选；QZ Tray 未连接、未找到真实打印机、存在多个未选设备时均有清晰提示。 |
| 打印语义 | QZ 接受时界面和日志显示“已提交/已接受”，没有额外证据时不显示“物理打印成功”。 |
| 日志 | 可按三类查看和清空，已提交/失败/超时/重复覆盖均可追溯；当前版本验证 100 条上限。 |
| BOL | 可多选渠道并分别保存数量；重复 BOL 单号不能保存；确认后可得到 Letter PDF 并记录版本、打印次数。 |
| 薪酬 | 能正确按周拆分 40 小时常规与超出部分 OT；缺基础时薪时阻断导出；导出文件包含两张指定工作表。 |
| 设置 | 可保存打印机与音效偏好；QZ 未签名或未连接时用户能看到下一步处理建议。 |

## 10. 已知缺口与建议优先级

| 优先级 | 缺口 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 私有面单磁盘备份和容量告警策略待落地 | 单机磁盘故障或容量耗尽会影响资产交付 | 把私有目录纳入加密备份与容量监控，或切换美国区对象存储。 |
| P0 | 打印日志仅保留 100 条，BOL 仅保留 5 条 | 无法满足运营留痕与正式归档 | 设计服务端数据模型、导出/检索和保留策略；至少先提升本机可配置容量。 |
| P0 | PDF 文件命名规则与实际匹配规则表述不完全一致 | 可能造成找不到面单或误导操作员 | 固化为一个模板规范，并在导入时执行预检与匹配率报告。 |
| P0 | BOL、考勤草稿和拦截名单仍只在浏览器本机保存 | 换机、清缓存、多人共用设备会丢失/泄露这些数据 | 按业务保留策略逐项迁移到受控后端；不要混入物流同步接口。 |
| P1 | “本日运营概览”“系统状态”仍为占位 | 管理者无法获得真实运行和产能视图 | 接入扫描量、成功率、失败原因、打印机健康、导入匹配率等真实指标。 |
| P1 | 仓库身份已覆盖云端物流与打印审计，但 BOL/考勤/拦截仍未关联用户 | 这些本机模块的修改仍无法跨设备追责 | 分模块增加服务端模型与审计，不复用上游客户凭据。 |
| P1 | BOL 使用浏览器打印窗口 | 现场打印可被弹窗策略影响，不能统一审计 | 评估浏览器打印或 QZ 的受控 PDF 输出；不引入 Node 轮询桥。 |
| P2 | 考勤规则内置为固定午休 1 小时、OT 1.5 倍、油补 $19.50/天 | 不适应不同站点或政策 | 将规则参数化，并记录生效日期与版本。 |

## 11. 发布前检查清单

- Windows 现场电脑已安装并运行 QZ Tray。
- 至少有一台真实标签打印机可发现并完成测试打印；虚拟设备未被误选。
- 生产环境配置 `QZ_CERTIFICATE`、`QZ_PRIVATE_KEY`（或 Base64 变量）和 `QZ_ALLOWED_ORIGINS`。
- 已使用真实 Excel、PDF 文件名样例验证导入匹配规则和失败提示。
- 已验证拦截、重复打印覆盖、QZ 失联、无打印机、多打印机等异常路径。
- 已告知现场：浏览器本地数据不等同于正式云端归档，清理浏览器数据会影响本机历史记录。
- 已确认上游 API Key 不存在于前端包、浏览器存储或仓库电脑配置。
- 自动闭环发布前须应用 `005`/`006` 迁移，配置主密钥和客户回调，完成上游验签/去重联调，并验证死信告警与人工重放；未完成时不得宣称生产闭环已上线。
