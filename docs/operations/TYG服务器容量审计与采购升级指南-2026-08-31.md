# TYG 服务器容量审计与采购升级指南

审计日期：2026-08-31  
审计方式：腾讯云国际站控制台只读检查、腾讯云自动化助手只读命令、项目配置核对。  
适用目标：TYG 集中推送 PDF Base64 面单；首期 1,200 请求/分钟；后续 50,000 单在 10 分钟内完成。

## 一、结论先行

当前 CPU 和内存不需要升级。现有 8 核 16 GB CVM 的空闲资源很多，当前业务的主要短板是：

1. 公网入站带宽只有 10 Mbps，无法稳定承接集中 PDF Base64 上传。
2. 只有一台服务器，API、MySQL、Redis 都在同一台机器上，任何主机故障都会导致整个接口不可用。
3. COS 对象存储尚未开通，PDF 仍指向本机磁盘方案。
4. MySQL 只有本机实例；当前数据库很小，但没有云数据库级别的跨可用区高可用。
5. API 只有一个 Node.js 进程，不能充分利用 8 个 CPU 核心。
6. 当前本地数据库备份量很小，不能证明已经具备可靠的异机恢复能力。
7. 当前 CVM 将于 2026-09-27 到期，应尽快续费，避免临近联调时停机。

推荐顺序：先续费现有 CVM，再处理 200 Mbps 测试带宽和 COS，然后购买高可用 MySQL；完成应用改造和压测后，再决定是否提高到 300–1,200 Mbps 以及是否购买第二台应用服务器。

## 五、API、Nginx、Redis 和备份

- API 健康检查成功，MySQL、Redis 和面单目录探针均正常。
- PM2 当前只有一个 `cloud-api`，模式为 `fork_mode`，没有配置多实例。
- Nginx 实际请求体上限为 50 MB；新 TYG 路由仍应单独限制为 7 MB，不能全局无限放大。
- 当前普通 JSON 上限为 256 KB，TYG Base64 路由尚未获得独立 7 MB 解析配置。
- Redis 正常响应，但 `maxmemory=0`，表示没有内存上限。
- 当前面单目录仅约 4 KB，尚无真实面单存量。
- 本机数据库备份目录只有 1 个很小的文件；必须建立可验证的自动备份与恢复演练。

## 六、为什么 10 Mbps 不够

腾讯云官方说明：当购买带宽小于或等于 10 Mbps 时，公网入站带宽也是 10 Mbps；购买值大于 10 Mbps 后，入站上限等于购买带宽。因此 TYG 上传也受当前 10 Mbps 限制。

Base64 会使文件体积增加约三分之一。50,000 单在 600 秒内传完的理论最低带宽如下，尚未包含 HTTPS、JSON 和网络波动：

| 平均原始 PDF 大小 | 理论最低带宽 | 建议购买/配置上限 |
|---:|---:|---:|
| 100 KB | 约 89 Mbps | 150–200 Mbps |
| 200 KB | 约 178 Mbps | 250–300 Mbps |
| 500 KB | 约 445 Mbps | 600 Mbps |
| 1 MB | 约 889 Mbps | 1,200 Mbps |
| 5 MB（单文件上限） | 约 4.4 Gbps | 单台普通 CVM 方案不适合 |

因此在承诺“10 分钟完成”前，必须让 TYG 提供至少 100 份真实 PDF 样本，计算平均值、P95 和最大值。单文件 5 MB 是保护上限，不能拿它当平均文件大小做容量承诺。

## 七、采购决策

### 立即购买或开通

#### 1. 续费现有 CVM

当前 CPU/内存无需变更，只续费即可。建议先续费 12 个月，并开启到期提醒。

控制台路径：

`腾讯云国际站 → 云服务器 CVM → 弗吉尼亚 → air-cargo-server → 续费 → 12个月 → 核对报价 → 支付`

不要购买更高 CPU 或更大内存。

#### 2. 将网络改为按流量计费、峰值 200 Mbps，作为联调和压测起点

TYG 属于集中突发上传，先采用按流量计费通常比长期购买 200–600 Mbps 固定带宽更合适。腾讯云按流量模式的上限为 200 Mbps，适合联调和第一阶段压测；超过 200 Mbps 的正式目标需要固定带宽、小时带宽或带宽包。

控制台路径：

`云服务器 CVM → 实例 → air-cargo-server → 更多 → 资源调整 → 调整网络`

选择：

- 网络计费：按流量计费。
- 带宽上限：200 Mbps。
- 先查看退款、补差价及切换次数提示，再提交。

包年包月固定带宽切换为按流量计费存在次数限制。不要未经报价复核就直接购买 500 Mbps 或 1 Gbps 固定带宽。

#### 3. 开通 COS 并创建私有面单桶

推荐设置：

- 地域：美国东部（弗吉尼亚），与 CVM 同地域。
- 桶名建议：`cmhub-labels-prod`，实际名称会附加账号 APPID。
- 存储类型：标准存储 STANDARD。
- 访问权限：私有读写。
- 版本控制：关闭。面单版本由应用使用不同对象 Key 管理。
- 服务端加密：开启 SSE-COS。
- 公网读：禁止。
- 生命周期作用范围：`labels/` 前缀或整个专用桶。
- 当前对象：最后修改 7 天后删除。
- 未完成分块上传：1 天后中止。

不要使用低频或归档存储：它们存在 30/90/180 天最低存储期，7 天删除可能产生提前删除费用。

控制台路径：

`对象存储 COS → 开通服务 → 存储桶列表 → 创建存储桶 → 完成以上设置 → 生命周期 → 新建规则`

开通 COS、同意协议和提交创建会产生云端资源及后续费用，实际操作前需再次确认。

#### 4. 购买高可用云 MySQL

技术和业务数据都要求可靠保存，而当前 MySQL 与 API 在同一台服务器上。建议在 TYG 正式生产前迁移到腾讯云 MySQL：

- 地域：弗吉尼亚。
- 版本：MySQL 8.0。
- 架构：双节点高可用、多可用区。
- 起步规格：4 vCPU、16 GB 内存。
- 存储：300 GB SSD 起步，开启容量告警。
- 网络：与现有 CVM 相同的 Default-VPC，使用内网地址。
- 公网访问：关闭。
- 自动备份：每天。
- 数据备份保留：30 天。
- Binlog 保留：30 天，用于时间点恢复。

控制台路径：

`云数据库 TencentDB → MySQL → 实例列表 → 弗吉尼亚 → 新建实例`

先按月购买 1 个月用于迁移和压测，稳定后再改长期订阅。当前业务数据只有约 3.14 MB，迁移窗口较短，是迁移的最佳时期。

### 暂时不买

1. 不升级当前 CVM 的 CPU 和内存。
2. 不扩大 50 GB 系统盘来保存 PDF；PDF 应进入 COS。
3. 不立即购买第二台服务器，先完成 COS、云 MySQL 和应用无状态化改造。
4. 不立即购买 500 Mbps–1.2 Gbps 固定带宽，先取得 TYG 真实 PDF 样本并压测。

### 正式上线前建议增加

1. 腾讯云 Redis：同地域、同 VPC、1 GB 高可用实例。当前容量不是问题，购买它是为了故障切换。
2. 第二台 API 服务器：至少 4 核 8 GB，与现有服务器组成双机并放到负载均衡后面。
3. 负载均衡 CLB：TLS 终止、健康检查和故障切换。

这些资源必须在 PDF 已迁移 COS、数据库已迁移云 MySQL、API 可以多进程运行之后再购买，否则增加服务器也不能形成真正高可用。

## 八、不属于采购但必须修改的配置

1. PM2 从单个 fork 进程改为 4 个 cluster worker；每进程内存上限建议 1 GiB。
2. TYG 路由单独设置 7 MB JSON 上限，鉴权通过后才解析正文。
3. 应用 MySQL 连接池每进程 10–15，总连接控制在 40–60。
4. 不得把 `labelBase64` 写入 MySQL 或普通日志。
5. Redis 设置 `maxmemory 256–512mb`、`maxmemory-policy noeviction`，并在 70% 使用率告警。
6. 安装腾讯云监控组件，使内存和文件系统使用率进入控制台监控。
7. 开启实例销毁保护，并创建每日系统盘快照策略。
8. 验证数据库恢复：至少每季度在临时环境做一次恢复演练。

## 九、推荐执行顺序

1. 续费现有 CVM。
2. 向 TYG 索取 100 份真实 PDF 样本及集中推送时间窗口。
3. 将网络临时调整为按流量 200 Mbps。
4. 开通并配置私有 COS 和 7 天生命周期。
5. 完成应用对象存储 Adapter 和 TYG 三个接口开发。
6. 购买并迁移高可用云 MySQL。
7. 进行 20 请求/秒压测。
8. 进行 100 请求/秒压测，根据真实 PDF 平均大小确定正式带宽。
9. 决定是否购买腾讯云 Redis、第二台 API 服务器和 CLB。

## 十、付款前核对清单

任何订单在支付前，确认以下内容：

- 地域必须是弗吉尼亚。
- VPC 必须与现有服务器一致。
- 没有误开公网数据库。
- COS 必须是私有读写、标准存储。
- MySQL 必须是双节点高可用，不是单节点。
- 带宽计费方式和峰值符合本次方案。
- 订单期限、自动续费、退款限制和优惠券规则已经看清。
- 将最终报价页截图或报价明细交给技术复核后再支付。
