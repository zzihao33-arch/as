# 空提列表跨页与批量窗口验收

## 本批结论

基线 `f24b767`。Chrome 对发布工作树进行了合成 API 浏览器验收，发现并修复一个真实前端竞态：打开批量窗口的目标读取尚未完成时切换筛选，选择已被清空，旧响应却仍打开旧提单窗口。筛选变化现在同时递增批量读取序号并结束其加载状态，沿用已有的迟到响应检查。

正式站点本轮打开后为登录页，尚未进行真实管理员业务验收。已请求用户自行登录并保留 Chrome 标签页。本报告的业务检查全部使用合成数据，不代表正式数据验收。

## 竞态回归：先失败，后通过

修复前：22:34:27.038Z 读取 fixture-19 并挂起；22:34:36.829Z 搜索已切换为 FIXTURE-001；释放旧响应后，列表显示 FIXTURE-001，但 dialog 仍为“批量入库确认 · 1 单”并包含 FIXTURE-019。浏览器断言“筛选变化后 dialog 数必须为 0”实际失败。

修复后：22:35:59.077Z 挂起 fixture-1 读取；22:36:15.558Z 搜索切换为 FIXTURE-019；确认新查询到达后释放旧响应。浏览器断言通过：dialog 数为 0、没有残留的“已选择 1 单”。随后选择 FIXTURE-019 可正常打开其入库窗口，显示最新 119 箱；未提交。

根因：手动取消选择、改变勾选和卸载已有 selectionSequence 失效处理，筛选变化的清空选择分支遗漏了这一步。修复仅补齐此分支；翻页不改变筛选，因此仍保留跨页选择。

## 复现方式

1. 在发布工作树运行 `node tests/fixtures/airPickupContinuityServer.mjs`（回环 4820）。另一个进程用 `VITE_CMHUB_API_BASE_URL=http://127.0.0.1:4820` 启动 Vite，监听回环 4819。环境变量仅用于该开发进程。
2. 浏览器进入 `http://127.0.0.1:4819/air-pickups`。fixture 自动提供合成会话；所有业务写请求均拒绝 405。
3. 用 `POST /__control?detailMode=hold` 挂起详情请求；勾选记录并点击批量入库。通过 `GET /__stats` 确认 pending=1 后改变关键词或客户筛选，确认新列表请求到达，再 `POST /__control?release=1&detailMode=ok`。
4. 等待旧请求 respondedAt 写入后，断言页面没有 dialog、旧选择已清空；新选择仍可打开正确窗口。交仓共享同一读取和失效逻辑。
5. `detailMode=fail` 测试读取失败，`detailMode=stale` 测试服务端状态变化，`limit=20` 测试末页恢复。交互前收起“更多筛选”浮层，避免遮挡按钮。Arco 复选框需点击对应 label。

请求证据：`air-pickup-continuity-acceptance-2026-09-18/request-events.json`，87 个业务请求均为 GET，业务写入 0，保存时 pending=0。
