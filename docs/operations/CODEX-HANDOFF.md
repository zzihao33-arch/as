## 当前目标

完成 TYG API v1.1 的实现、测试和联调；先稳定测试环境，再加固正式发布链路。正式上线前不得跳过测试验收。

## 已确认的业务规则

- TYG先预报：空运提单号、总箱数、总重量、重量单位、包裹数。
- 第一阶段面单推送字段：原单号、转单号、PDF Base64。
- 返回成功前，业务数据和PDF必须可靠保存。
- 每天可能集中推送几万单，目标尽量在10分钟内完成接收。
- 同一原单号重复上传即更新：PDF可替换；`A→B`可直接覆盖为`A→C`。
- 统一使用主推送接口完成新增和更新，不要求TYG调用独立换单接口。
- 提单关闭后仍允许补传、重传和更换面单。
- PDF存入私有COS，保留7天后自动删除；订单关系、状态和操作记录保留2年。
