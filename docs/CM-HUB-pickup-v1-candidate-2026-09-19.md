## 本批验证结果

- 前端：`npm test` 61/61，严格类型检查和生产构建通过。
- 后端：`CMHUB_T2_MYSQL_PORT=13319 npm test` 90/90，0跳过；严格类型检查、构建通过。14份迁移在一次性MySQL 8.4.11数据库中实际应用，测试结束删除合成schema。
- 回归包括真实HTTP、私有filesystem、大小/摘要校验、去重/额度/替换、权限撤销、上传租约恢复、提交回执未知、缺少检查器拒绝及关闭开关时不访问数据库。
- Office回归先失败于QUEUED，再修复为UNSUPPORTED并通过：不产生转换任务，原件附件下载字节不变，预览及无下载权限被拒绝。
- 本地浏览器（Edge/Playwright，构建产物，全量API拦截、外网请求阻断）通过：Office无查看按钮、图片查看、上传成功但响应丢失后只查询原编号（PUT仅一次）、权限恢复后移除上传/维护入口且只恢复一次会话、开关关闭隐藏入口、390px及1440px布局。运行时异常0。
- 独立复审发现正常续期会卸载表单；已修复，同账号续期保留入库表单及手工输入17。另补跨工作空间续期后工作站注册503的回归，确认显示重新连接而不永久loading。两项浏览器断言均已观察修复前失败、修复后通过。
- 移除仅为查询归属引入的无用T2/T3状态机，保留两字段归属辅助函数。
- MySQL回归额外发现发布基线查询别名`row_number`触发SQL语法错误，已仅改名为`attempt_rank`；真实提单创建/详情读取及凭证回归通过。本批不据此判断生产正在运行的后端版本。
- 构建仍有既存大于500kB分包提示；未把本次作为分包优化批次。

浏览器复现：先`npm run build`，再`node tests/pickupDocuments.browser.cjs`。脚本默认本机Edge及已有Playwright路径，可用`CMHUB_BROWSER_PATH`/`CMHUB_PLAYWRIGHT_MODULE`覆盖。无agent-browser命令，因此使用仓库既有Playwright方式完成浏览器验证。

完整日志、红灯证据、请求记录及截图在候选工作树`.cache/pickup-v1/`（git忽略）；当前摘要随源码提交。截图为合成数据，不含生产凭证。
